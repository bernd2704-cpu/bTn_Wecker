# bTn Wecker – Funktions- und Task-Referenz

*Firmware 20v21 · ESP32 / FreeRTOS*

## 1. FreeRTOS Tasks

9 Tasks auf Core 0 und Core 1. Priorität 2 > Priorität 1.

| Funktion / Task                              | Kategorie | Aufgabe                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| touchTask<br>Core 0 · Pri 2<br>Stack 2880    | Task      | Kapazitive Touch-Pads T0/T2/T3/T4 via ESP-IDF touch_pad_read(). State Machine TS_IDLE→TS_PRESSED→TS_REPEAT. Hold-Erkennung 750ms, Repeat 250ms. Exklusivität: nur ein Pad aktiv. Baseline-Rekalibrierung alle 10min im Idle. Zwangs-Reset auf TS_IDLE + Baseline-Neuerfassung nach TOUCH_MAX_HOLD_MS (30s) ununterbrochenem Kontakt – schützt vor einem klemmenden Pad (Feuchtigkeit/Kabeldefekt), das sonst unbegrenzt Events sendet (20v12/E1-Fix).                                                                                                                                                                                                                                                         |

Atomarer localtime_r()-Snapshot (inkl. tm_isdst) verhindert Race Condition mit displayTask. Core 0 trennt Task physisch von inputTask. Alarmstart läuft über triggerAlarm() (12v05ff., Absturzerkennung + Retry, siehe Abschnitt 3) und ruft dabei wakeDisplay() auf (10v03). Setzt wdg_alarmTask + esp_task_wdt_reset(). Wertet timeValid()-Gate vor jeder Alarm-/Kuckuck-Auswertung aus (20v04/A5-Fix) – keine Auslösung auf ungültiger Systemzeit (kein NTP-Sync seit Boot).                                                                                                                                            |
| wifiTask<br>Core 0 · Pri 1<br>Stack 2240     | Task      | Überwacht WiFi.status(), reconnect via WiFi.begin() (nicht disconnect()+reconnect(), das würde den SNTP-Client stören) nach WIFI_RECONNECT_MS. Schreibt Verbindungszeitpunkt in Double-Buffer (datum_WiFi_tmp/zeit_WiFi_tmp) nur wenn wifiSyncPending==false (Torn-Read-Schutz, 11v00), setzt wifiSyncPending=true.                                                                                                                                                                                                                                                                                                                                                                                           |
| nvrTask<br>Core 0 · Pri 1<br>Stack 2304      | Task      | Wartet auf nvrSemaphore. Wird auf der Web-Log-Seite als dedizierte Sektion angezeigt.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| watchdogTask<br>Core 0 · Pri 1<br>Stack 1344 | Task      | Software-Watchdog: prüft alle WDG_CHECK_MS (1s, seit 20v08) ob wdg_inputTask/displayTask/alarmTask innerhalb WDG_TIMEOUT_MS (10s, seit 20v08) aktualisiert wurden – feuert damit vor dem 15s-Hardware-TWDT. Bei Freeze: webLog + OLED-Meldung + ESP.restart(). Friert alarmTask während eines laufenden triggerAlarm()-Versuchs ein (alarmTriggerInFlight-Marker), setzt watchdogTask vor dem Neustart ebenfalls rtcRetryMagic – seit 20v06 redundant (triggerAlarm() setzt den Merker bereits selbst beim Start), als Sicherheitsnetz belassen (12v12).                                                                                                                                                      |
| webLogTask<br>Core 0 · Pri 1<br>Stack 4096   | Task      | HTTP-Log-Server auf Port WEBLOG_PORT (8080). Wartet auf WiFi, dann: GET / → HTML-Seite mit Auto-Refresh alle 20 s und farbiger Darstellung (grün/rot/gelb), inkl. Mühlrad-Motor-Pulsweiten-Slider (GET /motor, 0–100%, 12v03). GET /log → plain text. Sektionen: Ring-Puffer WEBLOG_LINES × WEBLOG_LINE_LEN, aufgeteilt in DFPlayer (alle Zeilen mit „DFPlayer" im Text, Titel zeigt Zeitstempel des letzten erfolgreichen Alarms snapAlarmTime, 12v08) und Allg. Log (übrige Zeilen, Titel zeigt NTP-Zeitstempel des letzten Resets, 9v8), „Verbindung – letzter WiFi Reconnect / NTP Sync" (WiFi+NTP analog Info-Seite, 11v01; umbenannt+unter Ring-Puffer verschoben 11v02), Touch-Baseline und Stack-HWM. |
| inputTask<br>Core 1 · Pri 2<br>Stack 2240    | Task      | Konsumiert inputQueue (50 ms-Timeout). S1/S2 ohne displayMutex. Alle anderen Events: displayMutex → uiDispatch() → uiTransition(). safeChange + safeChangeMs: nvrSemaphore erst nach NVR_COMMIT_DELAY_MS (2 s) Ruhezeit ohne weiteres Event freigeben (11v00). | displayTask<br>Core 1 · Pri 1<br>Stack 2176  | Task      | Aktualisiert OLED alle DISPLAY_UPDATE_MS (300 ms) unter displayMutex. Überträgt NTP/WiFi-Double-Buffer. Auto-Rückkehr zu UI_CLOCK nach AUTO_RETURN_MS (20 s). Schaltet OLED ab nach DISPLAY_TIMEOUT_MS (5 min) ohne Touch (10v00/10v02). Begrenzt außerhalb des displayMutex zusätzlich die Einschaltzeit von Licht/Mühlrad (Zugschalter S2) auf S2_TIMEOUT_MS (30 min, 12v02) – analog zur Auto-Rückkehr, aber unabhängig vom UI-State. Setzt wdg_displayTask + esp_task_wdt_reset().                                                                                                                                                                                                                        |

| updateDstDayFlags(nowTm)<br>nowTm                                                 | State Machine | 20v21: einmal pro Kalendertag (tm_yday-Guard) ermittelt, ob heute Frühjahrs- oder Herbst-Zeitumstellung ist. TZ-generisch über zwei mktime()/localtime_r()-Proben (Stunde 1 und Stunde 4, beide nie übersprungen/doppelt): ändert sich tm_isdst zwischen beiden, hat heute eine Umstellung stattgefunden (Richtung an isdst ablesbar). Differenz Ist-/Soll-Zeit muss im Nachholfenster ALARM_CATCHUP_MIN (60 min) liegen – fängt Zeitsprünge (NTP-Sync nach Stromausfall), Reboots im Alarmfenster und Zeitumstellungen ab. | triggerAlarm()<br>alarmNum,fileNo,min,failCount                                   | State Machine | Startet Sound+Motor+Licht für Alarm 1/2. Setzt vor dem riskanten Abschnitt den In-Flight-Marker alarmTriggerInFlight (12v12, siehe watchdogTask) sowie – seit 20v06 (B2-Fix) bereits hier statt erst im Fehlerpfad – den RTC-Merker (rtcRetryMagic), drained den Serial2-Puffer über die Bibliothek (drainSerial2Pre(), 12v14), setzt die Lautstärke mit Untergrenze ALARM_MIN_VOL (10, 20v12/E1-Fix – schützt gegen ein durch klemmendes Touch-Pad auf 0 heruntergezähltes vol), ruft playFolder() und wertet verifyPlayStarted() aus: PLAY_OK/PLAY_NO_SOUND → ALARM_RUNNING (lockAlarmDayGuard() NACH bestätigtem Start); PLAY_CANCELLED (20v12/20v15, bewusster Nutzerabbruch S1/Vorschau/Menü) → ALARM_IDLE ohne Neustart, Tages-Sperre trotzdem setzen; PLAY_CRASHED → RTC-Merker bleibt gesetzt, failCount++, ab ALARM_MAX_RESTARTS (3, 12v10) endgültiger Abbruch (roter [FEHLER]-Eintrag), sonst ESP.restart(). |
| verifyPlayStarted()<br>label,fileNo                                               | State Machine | Bestätigt nach playFolder(), dass der DFPlayer den Play-Befehl angenommen hat: bis zu VERIFY_PLAY_RETRIES (3) Versuche im Abstand von VERIFY_PLAY_DELAY_MS (500ms, 12v06) über readStateDrained(). st>0 ODER dfPlayerBusy() (BUSY-Pin, 20v02) → PLAY_OK. Liefert readState() ein -1 (jede Nicht-Feedback-Frame-Art, z.B. unaufgeforderte Play-Finished-Meldung), wartet die Funktion zusätzlich bis zu SERIAL2_FEEDBACK_GRACE_MS (100ms, 13v00) aktiv auf einen echten Feedback-Frame, statt sofort aufzugeben. drainSerial2Progress() (20v11/C2-Fix) räumt VOR der eigenen 0x42-Abfrage bereits im Puffer liegende Altframes ab, damit sie nicht als Antwort auf die aktuelle Abfrage fehlinterpretiert werden.
